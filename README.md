# studyvault

База знаний студента: личные конспекты с `[[ссылками]]` между ними и общая библиотека материалов, которые проверяет
модератор, с комментариями, оценками и избранным. Это REST API на Go; интерактивная документация открывается
прямо в браузере.

![CI](https://github.com/whoaskedssselery/studyvault/actions/workflows/backend.yml/badge.svg)

## Что умеет

- **Аккаунты.** Регистрация и вход, access JWT на 15 минут, refresh-токен в httpOnly cookie с ротацией:
  использованный токен второй раз отзывает всю сессию (защита от кражи), logout отзывает токен.
- **Роли.** Гость читает и ищет в библиотеке. Студент ведёт свои материалы, комментирует, оценивает и
  собирает избранное. Модератор проверяет материалы и ведёт общие предметы. Роль назначает только сервер
  (команда `promote`), через API её не получить.
- **Библиотека.** Материал проходит путь `draft → pending → published | rejected`. Опубликованное видят все,
  черновики, материалы на проверке и отклонённые только автор (и модератор для очереди). Правка опубликованного
  материала или его файлов возвращает его на проверку. Решение модератора и смена статуса одна транзакция;
  при отказе причина обязательна. Лента с фильтрами (предмет, тип, семестр), сортировкой по новизне, оценке и
  просмотрам и постраничной выдачей, поиск по опубликованному.
- **Комментарии, оценки, избранное.** Оценка 1 до 5, повторная обновляет прежнюю, среднее считается по
  сохранённым данным, «нет оценок» отдаётся как `null`. Свой материал оценить нельзя.
- **Снятие и отзыв.** Модератор может снять опубликованный материал с публикации с причиной: он становится отклонённым,
  автор видит причину, исправляет и отправляет заново, а оценки и комментарии сохраняются. Автор может забрать
  материал с проверки обратно в черновики.
- **Авторы.** Публичный профиль автора и рейтинг авторов: среднее арифметическое всех оценок всех его опубликованных
  материалов (при равенстве выше тот, у кого больше оценок, затем больше материалов). Ленту можно фильтровать по автору
  и по тегу, теги видны на карточках.
- **Аккаунт.** Сброс пароля по почте (одноразовая ссылка на час, хранится только хеш токена, ответ не выдаёт, есть ли такой
  аккаунт), смена пароля, удаление аккаунта с подтверждением паролем (вместе с данными и файлами в хранилище),
  правка своего комментария.
- **Предметы и заметки.** Заметки хранятся как документы редактора Tiptap (JSON). Мягкое удаление,
  постраничный список по курсору, фильтры по предмету, тегу и закреплению.
- **Теги.** Свои у каждого пользователя; набор тегов заметки заменяется атомарно.
- **Связи и граф.** Ссылки `[[Название заметки]]` в тексте превращаются в связи: обратные ссылки и граф
  заметок. Ссылка на заметку, которая появится позже, подхватывается сама.
- **Поиск.** Meilisearch: русский и английский, устойчив к опечаткам, с подсветкой найденного.
  Результаты всегда перепроверяются в Postgres, чужие и удалённые заметки не просачиваются.
- **Файлы.** PDF, PNG, JPEG и WebP до 2 МБ, до 3 файлов на материал. Загрузка идёт напрямую в S3-хранилище по временной ссылке,
  подпись которой привязана к заявленным типу и размеру, так что залить другое по ней нельзя.

## Стек

Go · chi · PostgreSQL (pgx, sqlc, goose) · Meilisearch · S3 (RustFS) · JWT + bcrypt ·
OpenAPI (oapi-codegen) · Docker Compose · GitHub Actions.

## Быстрый старт

Нужен только Docker.

```bash
cp .env.example .env
docker compose --profile app up -d --build
```

Поднимутся Postgres, Meilisearch, S3-хранилище, миграции и сам API. Дальше:

- **http://localhost:8080/docs** — Swagger UI: все эндпоинты, кнопка **Authorize** для токена,
  **Try it out** для запросов;
- http://localhost:8080/health — проверка сервиса и базы (то же по адресу `/v1/health`);
- http://localhost:8080/openapi.yaml — контракт для генерации клиентов.

Как попробовать в Swagger UI: `POST /auth/register` → скопировать `access_token` из ответа →
**Authorize** → вставить токен → пользоваться остальными эндпоинтами.

**Демо-данные.** Чтобы увидеть библиотеку заполненной (модератор, студенты, материалы во всех статусах,
комментарии и оценки), выполните один раз:

```bash
docker compose --profile app run --rm --entrypoint /seed api
```

Войти можно как `moderator@example.com` или `demo@example.com` с паролем из `SEED_PASSWORD` (в `.env.example`
это `demo-password-123`). Любого другого пользователя в модераторы переводит команда
`docker compose --profile app run --rm --entrypoint /promote api почта@пример.ру`.

**Почта.** Письма со ссылками сброса пароля и подтверждения почты локально ловит Mailpit: окно со всеми письмами http://localhost:8025.
Куда ведут ссылки, задают `PASSWORD_RESET_URL` и `EMAIL_VERIFY_URL` (в `.env.example` это страницы клиента на порту 5173). Новый аккаунт
до подтверждения почты не может публиковать, комментировать и оценивать; демо-аккаунты из seed подтверждены.

Остановить: `docker compose --profile app down` (данные сохраняются в томах).

## Разработка

Нужен Go (версия указана в `backend/go.mod`).

```bash
cp .env.example .env
docker compose up -d                      # только инфраструктура
cd backend
go tool goose -dir migrations postgres "$DATABASE_URL" up   # миграции (DATABASE_URL из .env)
go run ./cmd/api                          # API на :8080, .env подхватывается сам
go test ./...                             # тесты
```

Тесты идут на настоящих Postgres, Meilisearch и S3 (транзакции откатываются, индексы и бакеты
временные). Если сервисы не подняты или переменные не заданы, соответствующие тесты пропускаются.
Перед тестами выгрузите переменные: `set -a; . ../.env; set +a`.

| Порт | Сервис |
|---|---|
| 8080 | API |
| 5440 | PostgreSQL |
| 7700 | Meilisearch |
| 9000 / 9001 | S3-хранилище / его консоль |

Полезные команды (из каталога `backend`):

```bash
go generate ./internal/httpapi/                                        # код сервера из api/openapi.yaml
docker run --rm -v "$PWD:/src" -w /src sqlc/sqlc generate              # код запросов из internal/db/queries
go run ./cmd/reindex                                                   # пересобрать поисковый индекс из базы
```

## Настройки

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres (обязательна) |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов (обязателен) |
| `HTTP_PORT` | порт API, по умолчанию 8080 |
| `COOKIE_SECURE` | по умолчанию `true`: refresh-cookie уходит только по HTTPS. `false` нужен лишь для локальной работы по http |
| `AUTH_RATE_LIMIT_PER_MIN` | попыток входа, регистрации, обновления токена и смены пароля в минуту с одного адреса, по умолчанию 20; `0` выключает. Считается по адресу соединения, за обратным прокси лимит нужно задавать на самом прокси |
| `CORS_ORIGINS` | адреса фронтенда через запятую; только явные, без `*` |
| `LOG_FORMAT`, `LOG_LEVEL` | лог: `json` (по умолчанию) или `text`; уровень `debug`, `info` (по умолчанию), `warn`, `error` |
| `MEILI_URL`, `MEILI_MASTER_KEY` | поиск; без них `/search` отвечает 503, остальное работает |
| `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | файлы; без них `/attachments` отвечает 503 |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `PASSWORD_RESET_URL`, `EMAIL_VERIFY_URL` | почта для сброса пароля и подтверждения адреса; без `SMTP_HOST` сброс отвечает 503, а подтверждения нет (аккаунты подтверждены сразу). Локально это Mailpit, настроен в compose |
| `TRUSTED_PROXIES` | адреса или сети прокси через запятую, которым доверяется `X-Forwarded-For` при определении клиента для лимита попыток; пусто: заголовок игнорируется. `0.0.0.0/0` не принимается |
| `SEED_PASSWORD` | пароль демо-аккаунтов для команды `seed` (только для локальной работы; без неё пароль генерируется и печатается) |
| `S3_PUBLIC_ENDPOINT`, `S3_USE_SSL`, `S3_REGION` | адрес в ссылках для клиента, если он отличается; TLS; регион |

## API

Все эндпоинты живут под префиксом версии **`/v1`** (например, `POST /v1/auth/login`); в таблице ниже и в Swagger UI
пути даны без него. Вне версии остаются только `/docs`, `/openapi.yaml` и проба живости `/health` (она же `/v1/health`).
Все эндпоинты, кроме `/health`, `/auth/*` и чтения библиотеки (`GET /library...`), требуют заголовок
`Authorization: Bearer <access_token>`. Если токен к чтению библиотеки приложен, он должен быть действующим.
Подробности, схемы и примеры смотрите в Swagger UI. Там же описаны каталог кодов ошибок, лимиты,
пагинация и политика версий.

| Метод и путь | Что делает |
|---|---|
| `POST /auth/register`, `/auth/login` | регистрация, вход |
| `POST /auth/refresh`, `/auth/logout` | обновление токена (cookie), выход |
| `POST /auth/password-reset`, `/auth/password-reset/confirm` | сброс пароля по почте: запрос ссылки и новый пароль по ней |
| `GET /me`, `PATCH /me`, `DELETE /me` | свой аккаунт (с ролью), смена имени и факультета, удаление аккаунта с паролем |
| `POST /me/password` | смена пароля: остальные сессии завершаются, текущая продолжается |
| `POST /auth/email-verification/confirm`, `POST /me/email-verification` | подтверждение почты по ссылке из письма; повторная отправка письма (не чаще раза в минуту) |
| `GET /subjects`, `POST /subjects` | список и создание предметов |
| `PATCH /subjects/{id}`, `DELETE /subjects/{id}` | изменение и удаление предмета |
| `GET /notes`, `POST /notes` | список (по курсору, с фильтрами) и создание заметки |
| `GET /notes/{id}`, `PATCH /notes/{id}`, `DELETE /notes/{id}` | заметка целиком, изменение, мягкое удаление |
| `PUT /notes/{id}/tags` | заменить набор тегов заметки |
| `GET /notes/{id}/backlinks` | заметки, которые ссылаются на эту |
| `GET /graph` | граф связей между заметками |
| `GET /tags`, `POST /tags`, `DELETE /tags/{id}` | теги |
| `GET /search?q=` | полнотекстовый поиск |
| `POST /notes/{id}/submit` | отправить материал на проверку |
| `GET /library` | лента опубликованных материалов; с `q` поиск; фильтры `library_subject_id`, `kind`, `semester`, `author_id`, `tag`, сортировка `sort=new\|rating\|views` |
| `GET /library/{id}` | страница материала (гостю только опубликованный), считает просмотр |
| `GET /library/{id}/attachments/{attachment_id}` | ссылка на скачивание файла материала |
| `GET`, `POST /library/{id}/comments`, `PATCH`, `DELETE /comments/{id}` | комментарии: читать, оставить, изменить (автор), удалить (автор или модератор) |
| `PUT /library/{id}/rating` | поставить или изменить оценку 1 до 5 |
| `PUT`, `DELETE /library/{id}/bookmark`, `GET /bookmarks` | избранное |
| `GET /library-subjects` (гостю тоже), `POST /library-subjects`, `PATCH`, `DELETE /library-subjects/{id}` | общие предметы; менять может модератор |
| `GET /moderation/queue`, `POST /moderation/{id}/decision` | очередь проверки и решение (модератор) |
| `POST /moderation/{id}/unpublish` | снять опубликованный материал с публикации с причиной (модератор) |
| `POST /notes/{id}/withdraw` | забрать материал с проверки обратно в черновики |
| `GET /ranking/authors`, `GET /authors/{id}` | рейтинг авторов и публичный профиль автора (гостю тоже); материалы автора: `GET /library?author_id=` |
| `POST /attachments` | зарегистрировать файл, получить ссылку для загрузки |
| `GET /attachments?note_id=`, `GET /attachments/{id}`, `DELETE /attachments/{id}` | файлы заметки, ссылка на скачивание, удаление |

**Загрузка файла** идёт в три шага: `POST /attachments` возвращает `upload_url` → клиент делает `PUT` на этот адрес
с теми же `Content-Type` и `Content-Length`, которые заявил (без токена) → `GET /attachments/{id}` отдаёт ссылку на скачивание.

Ошибки приходят в формате [RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) (`application/problem+json`):
`type`, `title`, `status`, `detail` плюс стабильный `code` и `request_id` (он же заголовок `X-Request-ID`). Все коды
описаны в [docs/errors.md](docs/errors.md). Чужие заметки, предметы, теги и файлы отвечают 404, как и несуществующие.

Квоты на пользователя: 5000 заметок (удалённые не считаются), 200 предметов, 500 тегов, 3 файла на заметку, 5000 файлов и 1 ГиБ суммарно; сверх этого API отвечает
409 `limit_reached`. Вложения: PDF, PNG, JPEG и WebP, до 2 МБ.

## Схема базы данных

## Безопасность

Пароли хранятся как bcrypt, refresh-токены только в виде sha256, JWT принимается только с алгоритмом HS256 и
обязательным сроком. Все данные привязаны к пользователю на уровне SQL. Ответы API не кэшируются, весь текст
в сниппетах поиска экранирован, а загруженные файлы отдаются как вложения из белого списка типов
(без HTML и SVG). Тесты проверяют изоляцию пользователей на настоящей базе и ломались намеренно (мутациями),
чтобы убедиться, что они действительно ловят утечки.
Остальное: строгая политика CSP и запрет встраивания в чужие фреймы на каждом ответе, лимит попыток входа и смены
пароля, смена пароля стирает все прочие сессии, истёкшие refresh-токены удаляются по расписанию.

## Эксплуатация

- **Логи.** Одна JSON-строка на запрос (метод, шаблон маршрута, статус, длительность, `request_id`), без query string,
  заголовков и конкретных id. `request_id` же возвращается клиенту в заголовке `X-Request-ID` (безопасный
  заголовок клиента сохраняется), так что по жалобе пользователя нужную строку лога находят сразу.
  `LOG_FORMAT=text` удобнее читать глазами. Паника обработчика превращается в обычный ответ 500 в формате API.
- **Остановка.** По сигналу сервер перестаёт принимать запросы и до 10 секунд дорабатывает начатые.
- **Здоровье.** `GET /health` проверяет базу; без Meilisearch и S3 остальное API продолжает работать.

## Проверки

Всё это идёт в GitHub Actions на каждый push:

- форматирование, `go vet`, `staticcheck`, `govulncheck` (уязвимости, которые код действительно вызывает);
- сгенерированный код совпадает с контрактом и SQL-запросами;
- тесты с `-race` на настоящих Postgres, Meilisearch и S3. **Пропущенный тест считается провалом**: без сервисов
  такие тесты пропускаются молча, и зелёный прогон ничего бы не доказывал;
- fuzz-тесты разборщиков документов и курсора (`go test -fuzz=FuzzParseLinks ./internal/note`, из каталога `backend`);
- покрытие написанного вручную кода не ниже 85% (сейчас около 92%; сгенерированный код не считается);
- сквозной прогон: образ собирается, стек поднимается командой из этого README, и скрипт
  [scripts/smoke.sh](scripts/smoke.sh) проходит основной путь пользователя через настоящий HTTP. Его можно запустить
  и локально, когда стек поднят: `bash scripts/smoke.sh`.
