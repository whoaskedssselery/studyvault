# Запуск и проверка фронтенда StudyVault

Основной интерфейс работает с Go API: библиотека, конспекты, поиск, авторы и рейтинг доступны гостю. Вход открывает личные материалы, избранное и настройки аккаунта. Подтверждённая почта нужна для публикации, комментариев и оценок. Модератору доступна очередь проверки и управление общими предметами.

## Запуск на Windows

Установите Node.js 22 и запустите Docker Desktop с Linux-контейнерами. В PowerShell:

```powershell
cd D:\spo2\studyvault
git pull --ff-only origin main
if (!(Test-Path .env)) { Copy-Item .env.example .env }
docker compose --profile app up -d --build
docker compose --profile app run --rm --entrypoint /seed api
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173/. Письма подтверждения и сброса пароля приходят в локальный Mailpit: http://localhost:8025/. API и Swagger доступны по http://localhost:8080/docs.

Демоаккаунты после seed: `demo@example.com` (студент) и `moderator@example.com` (модератор). Пароль в примере .env — `demo-password-123`; если вы изменили SEED_PASSWORD, используйте своё значение. Их почта уже подтверждена.

Существующий .env команда не перезаписывает. Для прямой загрузки в RustFS нужны разрешённые адреса браузера: настройка S3_CORS_ORIGINS из нового .env.example либо значения по умолчанию Compose. После её изменения пересоздайте сервис: `docker compose up -d s3`. Для писем адрес фронтенда задают PASSWORD_RESET_URL и EMAIL_VERIFY_URL; по умолчанию это localhost:5173.

## Что подключено

- Гостевые библиотека, поиск с безопасной подсветкой, фильтры, страницы по курсору, материалы, вложения, рейтинг и профили авторов. Поиск q возвращает одну страницу по контракту.
- Вход, регистрация, выход, восстановление сессии через refresh-cookie; актуальная роль и профиль получаются из GET /me.
- Подтверждение почты и повторная отправка с обратным отсчётом Retry-After; восстановление пароля. Одноразовый токен убирается из адреса до запуска роутера и не сохраняется в браузерных хранилищах.
- Черновики, Tiptap, общие и личные предметы, теги, закрепление у себя, отправка и отзыв с проверки. Правка опубликованного материала возвращает его на модерацию.
- PDF, PNG, JPEG, WebP: до 3 файлов по 2 МБ. Браузер загружает файл напрямую по подписанной S3-ссылке без Bearer-токена. При сбое можно повторить загрузку или удалить запись.
- Комментарии, изменение и удаление своего комментария, оценки, избранное. Собственный материал оценивать нельзя.
- Одобрение, отклонение с причиной, снятие публикации, создание/изменение/удаление общих предметов для модератора.
- Имя и факультет, смена пароля, удаление аккаунта с вводом пароля, меню пользователя, светлая и тёмная темы.

Контракт — backend/api/openapi.yaml. Типы src/api/schema.d.ts генерируются перед dev/build и не хранятся в Git: обновление контракта не оставляет CI со старой копией. Ошибки RFC 7807 отображаются по code; HTTP 429 учитывает Retry-After. Идентификаторы запросов и технические страницы не выводятся в обычном меню.

## Учебные index.html и mock.json

Готовая сборка находится в deliverables/frontend. Она по умолчанию работает на mock.json без API:

```powershell
cd D:\spo2\studyvault\deliverables\frontend
node serve.mjs --port 4174
```

Откройте http://localhost:4174/. Для этого же HTML с настоящим API — http://localhost:4174/?mode=api#/. Для возврата к мокам — http://localhost:4174/?mode=demo#/. Выбор сохраняется в localStorage. В исходном приложении аналогично можно открыть http://localhost:5173/?mode=demo.

Учебные действия сохраняются локально и не переносятся на сервер автоматически. На статическом хостинге два файла работают в деморежиме; реальный API требует прокси. Двойной клик file:// не подходит для fetch mock.json.

## Маршруты и сборка

В dev и переносимом HTML запросы /backend-api/* проксируются в /v1/*, cookie Path переписывается в /backend-api/auth. Production-сборка использует /v1/* напрямую, как настроено в deploy/Caddyfile; для неё задайте FRONTEND_DIR=./frontend/dist вместо учебной папки по умолчанию. Access-токен хранится только в памяти. Просроченная гостевая сессия обновляется или очищается, после чего чтение библиотеки продолжается без авторизации.

```powershell
cd D:\spo2\studyvault\frontend
npm run package:submission
npm run test:proxy
npm test
```

Сборка проверяет TypeScript приложения и тестов. Браузерные проверки охватывают деморежим, основной интерфейс на подставленных HTTP-ответах, production-маршруты и переносимый HTML. Отдельный `npm run test:integration` требует поднятого Docker-стека и seed: он использует настоящий API, Mailpit, PostgreSQL и RustFS. В CI этот стек поднимается автоматически. Результаты и границы проверки описаны в docs/assignment-2/frontend-report.md.

Служебные /workspace и /api-status оставлены для разработки и не находятся в меню. Для полного удаления учебных данных очистите studyvault.database.v1 и studyvault.session.v1; тема и режим сохраняются отдельно.
