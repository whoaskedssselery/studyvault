# Frontend StudyVault

Интерактивный интерфейс на фейковых данных. Начальная библиотека читается отдельным HTTP-запросом из `frontend/public/mock.json`, действия сохраняются в localStorage. Сервер не нужен для библиотечных сценариев. Вход и регистрация имитируются; используйте только вымышленные данные и пароли.

## Запустить исходники

Нужен Node.js 20.19+ или 22.12+.

```powershell
cd D:\spo2\studyvault\frontend
npm ci
npm run dev
```

Обычно открывается http://127.0.0.1:5173. После первых действий начальные материалы берутся из сохранённой локальной копии, поэтому изменение mock.json не заменяет ваши публикации автоматически.

## Файлы по заданию

`deliverables/frontend/index.html` содержит собранные React, CSS и JavaScript. Соседний `mock.json` — отдельные фейковые данные. Эти два файла можно передать тимлиду и разместить на статическом HTTP-хостинге. В этой сборке навигация через `#/…`, поэтому дополнительная настройка SPA-маршрутов на хостинге не требуется. `serve.mjs` — необязательный локальный сервер, подробности в [инструкции комплекта](../deliverables/frontend/README.md).

```powershell
cd D:\spo2\studyvault
node deliverables/frontend/serve.mjs
```

Открыть http://127.0.0.1:4173/. Через `file://` браузеры ограничивают fetch локального JSON; показывается сообщение с предложением открыть HTTP-сервер.

## Проверки и пересборка

```powershell
cd frontend
npx playwright install chromium
npm run package:submission    # TypeScript, production-сборка, обновление сдаваемых файлов
npm test                     # UI, загрузка JSON, экспорт, API-ответы, сборка, mobile
```

Серверы тестов работают на 5173 и 4174. Изолированные браузерные контексты не меняют данные открытого пользовательского браузера. Снимки прошлого этапа обновляются в `docs/screenshots/`, снимки сдаваемой сборки — в `docs/assignment-2/screenshots/`. Там же сохраняется фактический результат проверки доступности локального API.

## Реализованные сценарии

- Библиотека: поиск по названию, содержимому и тегам, предметы, семестры, тип материала, сортировка, карточки/список.
- Чтение конспекта, комментарии, оценки 1–5, избранное.
- Tiptap: заголовки, полужирный, курсив, списки, блоки кода. Создание, сохранение и повторное редактирование черновиков.
- Отправка на проверку, одобрение и отклонение с причиной. Отредактированный материал проходит модерацию заново.
- Скачивание материала в Markdown. Подтверждаемое удаление собственного локального материала.
- PDF/PNG/JPEG/WebP: до 2 МБ на файл, не более 3 файлов. Файлы доступны для скачивания. Квота localStorage ограничена; при переполнении сохранение не считается успешным.
- Демовход, регистрация, профиль, рейтинг и модерация. Демоаккаунт Алексея открыт по умолчанию; после выхода — кнопка «Войти в демо».
- Ctrl+K / Cmd+K, мобильное меню, пустые состояния, ошибки JSON и повторная загрузка.
- Отдельная диагностика API: HTTP-статусы, проверка Content-Type и JSON-формата, сохранение результатов в файл.

## Что изменилось на сервере

В `main` на момент начала работы (0cb885d) есть Docker Compose, миграции, Go-сервер, health check, регистрация/вход/refresh/logout, CRUD предметов и CRUD заметок с soft delete и keyset pagination. Реальный контракт — `backend/api/openapi.yaml`. Теги, поиск, вложения, связи и граф объявлены в контракте, но пока отвечают 501 через `Unimplemented`.

Контракт API и демомодель фронтенда **различаются**. На сервере материалы и предметы принадлежат пользователю; общая библиотека, комментарии, рейтинг и модерация пока демонстрационные.

| Данные фронтенда | Серверный контракт |
| --- | --- |
| `User.name` | `User.display_name` |
| `Note.subject` — название | `Note.subject_id` — UUID; название из `/subjects` |
| `Note.content` | TiptapDoc в `content` |
| `Note.tags` — строки | `tags` — массив объектов `{id, name}` |
| `Note.createdAt` | `created_at`, дополнительно `updated_at` |
| `saves`, `ratings`, `comments`, `status`, `views` | В текущем Note-контракте этих полей нет |

При подключении API нужен адаптер этих моделей и мутации TanStack Query; подмена всего mock.json ответом `/notes` не сработает, поскольку список заметок не содержит content, users и демонстрационные поля. Общие материалы и социальные функции надо согласовать с бэкендером. Документация API в `.docx` остаётся вкладом аналитика; фронтенд её не подменяет.

## Диагностика JSON

Откройте `/api-status` в режиме разработки или `#/api-status` в сдаваемой сборке. Кнопка проверяет:

- `GET /health` → 200 и `{"status":"ok"}`; 503 означает недоступную БД.
- `GET /notes`, `GET /subjects` без Bearer-токена → 401 и JSON-ошибка `error.code` / `error.message`.

Это не проверка CRUD и не авторизация демоаккаунта на сервере. Запросы идут через `/backend-api`, который проксируется на `http://127.0.0.1:8080`. В Vite адрес можно изменить в `.env.local` по образцу `frontend/.env.example`; для готового `serve.mjs` — переменной окружения `STUDYVAULT_API_TARGET`. Секреты и токены не записываются в отчёт.

## Ограничения

Нет интеграции UI с настоящими аккаунтами, MinIO, Meilisearch и обмена данными между устройствами. Роль модератора демоаккаунта не является серверной защитой. Стартовые оценки и просмотры — демонстрационные; реальный счётчик чтений не обновляется. Wiki-ссылки, граф и собственные предметы пока не реализованы. Bundle включает редактор; перед production-развёртыванием стоит разделить страницы ленивой загрузкой.

Для сброса удалите ключи `studyvault.database.v1` и `studyvault.session.v1` через DevTools. Это удалит ваши локальные демоаккаунты, публикации и вложения.
