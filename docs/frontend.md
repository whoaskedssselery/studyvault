# Запуск фронтенда StudyVault

## Готовый сайт — одной командой

Нужен работающий Docker Desktop с Linux-контейнерами. Node.js и npm на компьютере для этого режима не требуются: сборка выполняется внутри Docker.

Откройте Docker Desktop один раз и дождитесь состояния Engine running. Из корня репозитория:

```powershell
.\start.ps1
```

Или дважды нажмите **start.cmd** в Проводнике. Скрипт собирает фронтенд и API, запускает PostgreSQL, Meilisearch, RustFS и Mailpit, проверяет API и добавляет демоматериалы. Существующий .env не перезаписывается; повторный seed не создаёт дубликаты.

Сайт: http://localhost:5173/?mode=api. Письма: http://localhost:8025/. Swagger: http://localhost:8080/docs.

| Роль | Почта | Пароль из примера .env |
| --- | --- | --- |
| Студент | demo@example.com | demo-password-123 |
| Модератор | moderator@example.com | demo-password-123 |

Если SEED_PASSWORD изменён, используйте своё значение. Почта демоаккаунтов подтверждена. Новые аккаунты получают письмо в Mailpit.

Без открытия браузера: `.\start.ps1 -NoBrowser`.

Остановка без удаления данных:

```powershell
docker compose --profile app --profile web stop
```

## Что работает

Гостевая библиотека, фильтры, поиск по тексту и Ctrl+K, материалы и авторы, рейтинг, комментарии, оценки, избранное. После входа доступны личные конспекты, профиль, смена пароля, подтверждение почты, восстановление пароля и удаление аккаунта.

Редактор сохраняет Tiptap JSON, метаданные, теги и предметы. Показывает несохранённые изменения и предупреждает при уходе. Поддерживает списки, цитаты, заголовки, код, отмену и повтор. Файлы PDF/PNG/JPEG/WebP — до трёх по 2 МБ, с прямой загрузкой в RustFS.

Статусы: черновик → на проверке → опубликован или отклонён. В панели активности видны последние статусы своих материалов. Модератор рассматривает заявки, снимает публикации с причиной и управляет общими предметами. Правка опубликованного конспекта возвращает его на проверку.

Есть тёмная тема, мобильное меню, выбор предметов, справка, управление с клавиатуры и восстановление страницы после ошибки загрузки. В обычном меню нет служебных страниц API.

## Переносимый вариант для учебного задания

```powershell
.\start.ps1 -Mode demo
```

Нужен Node.js; Docker для этого режима не требуется. Откройте http://localhost:4174/?mode=demo. Комплект index.html + mock.json находится в deliverables/frontend; интерфейс и действия работают локально в браузере.

Для этого же HTML с настоящим API используйте http://localhost:4174/?mode=api#/. Запросы /backend-api/* проксируются в /v1/*, Path refresh-cookie переписывается. API запускается отдельно; основной Docker-сайт уже включает его.

## Разработка

Для редактирования исходников нужен Node.js 22. Если Docker-фронтенд уже занял порт 5173, остановите только его:

```powershell
docker compose --profile app --profile web stop frontend
cd frontend
npm ci
npm run dev
```

API остаётся на порту 8080. Dev-сервер использует /backend-api, а production-сборка — /v1. В Docker Nginx обслуживает страницы и проксирует API; переходы по прямым ссылкам поддерживаются.

Типы генерируются перед dev/build из backend/api/openapi.yaml. Access-токен хранится в памяти, вход восстанавливается через refresh-cookie и GET /me. Одноразовые токены писем убираются из адреса до загрузки интерфейса и не сохраняются в браузерных хранилищах.

Редактор и учебная демоверсия загружаются отдельно. Для production используется dist с отдельными JS-частями; для учебного HTML создаётся отдельный dist-submission со встроенным кодом. Нельзя вручную собирать переносимый HTML из обычного dist.

## Проверки и скриншоты

```powershell
cd frontend
npm run package:submission
npm run test:proxy
npm test
```

53 браузерных сценария проверяют клиент и учебную сборку; HTTP-ответы API в них подставлены. Три Node-теста проверяют прокси.

Сквозной тест использует настоящий стек:

```powershell
$env:STUDYVAULT_BASE_URL = 'http://localhost:5173'
npm run test:integration
```

Тест создаёт временный аккаунт, читает подтверждение из Mailpit, загружает PDF, публикует его через модератора, проверяет гостевое скачивание и удаляет временный аккаунт. В frontend CI поднимается весь Docker-сайт, включая Nginx.

Снять скриншоты готовой версии:

```powershell
cd frontend
node scripts/capture-ready.mjs
```

Они сохраняются в docs/submission/screenshots; capture.json содержит дату, коммит, источник данных и результат проверки ошибок браузера. Для изменённого пароля seed задайте SEED_PASSWORD в окружении процесса.

Готовые материалы и сценарий показа — в [комплекте для сдачи](submission/README.md).
