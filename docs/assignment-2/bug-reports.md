# Проверки и баг-репорты

Дата обновления: 23 октября 2026. Основание серверного кода: main, коммит 06016a4; минимальная версия Go обновлена до 1.27.3. Первичная проверка была на 0cb885d; устаревшие замечания перепроверены. Актуальный комплект: [готовый сайт и проверки](../submission/README.md).

## Границы результатов

53 браузерных сценария проверяют клиент (API-ответы в них подставлены через page.route); 3 Node-теста проверяют прокси. 23 октября сквозной сценарий пройден локально через production preview и через готовую Docker/Nginx-сборку, без подстановок. Проверены Go API, PostgreSQL, Mailpit и RustFS: регистрация, подтверждение почты, заметка, PDF, модерация, гостевое скачивание и удаление аккаунта. api-check.json теперь содержит результат доступного локального API.

### FE-005 · Потеря несохранённого текста при переходе

Статус: исправлено. Редактор отслеживает изменения текста и метаданных. Переход требует выбора «Остаться» или «Уйти без сохранения», закрытие вкладки использует beforeunload. Успешное сохранение снимает предупреждение, ошибка сервера сохраняет его. Проверено readiness.spec.ts.

### FE-006 · Кнопки поиска и уведомлений показывали подсказки вместо интерфейса

Статус: исправлено. Ctrl+K и быстрый поиск открывают диалог с серверным поиском и управлением с клавиатуры. Панель активности читает статусы собственных заметок; гость получает предложение войти без запроса личных данных. Выбор предметов и справка также открывают рабочие панели.

### CI-003 · Уязвимая patch-версия стандартной библиотеки Go

Статус: версия обновлена. Проверка govulncheck в GitHub остановилась на GO-2026-6809 для Go 1.27.2. В go.mod требуется 1.27.3, в которой исправление уже есть. Docker-образ golang:1.27-alpine также использует 1.27.3. Источник: https://pkg.go.dev/vuln/GO-2026-6809. Проверка уязвимостей сохраняется.

### SEC-001 · Параметры ссылок писем в журнале веб-сервера

Статус: исправлено. Стандартный access log Nginx включает строку запроса с параметрами. Для Docker-фронтенда задан отдельный формат с $uri без параметров и без Referer. Сквозной CI после подтверждения почты проверяет, что token не оказался в журнале; при ошибке выводится только сообщение, без самой ссылки.

### INT-005 · Браузер блокировал прямую загрузку в RustFS

Приоритет P1, статус: исправлено и проверено на реальном стеке. В первом frontend full-stack CI API зарегистрировал файл, но браузер не смог выполнить PUT по подписанной ссылке: в Docker Compose отсутствовал RUSTFS_CORS_ALLOWED_ORIGINS.

Исправление: явные локальные адреса через S3_CORS_ORIGINS, без wildcard; Compose передаёт их RustFS. Сквозной тест проверяет preflight-заголовок, успешный браузерный PUT без Authorization и содержимое файла при гостевом скачивании. Ссылка с подписью не записывается в отчёт. Документация настройки: https://docs.rustfs.com/en/administration/cors.

### FE-004 · Повторное сохранение после ошибки тегов могло создать дубликат

Приоритет P2, статус: исправлено. Создание заметки и назначение тегов — два запроса. Если второй запрос не прошёл, новый материал уже существует на сервере.

Исправление: сохранить его ID и перейти к редактированию с сообщением о частичном сохранении. Регрессионная проверка live.spec.ts воспроизводит 409 limit_reached при создании тега и подтверждает, что повторный запрос обновляет заметку (PATCH), а POST /notes остаётся единственным.

### CI-002 · Проверка реального стека отсутствовала во frontend CI

Приоритет P1, статус: исправлено. Подставленные ответы успешно имитировали S3 PUT, хотя настоящая загрузка блокировалась браузером. Добавлен отдельный full-stack job: Docker Compose, seed, Mailpit и реальный браузер. Типы интеграционного теста проверяются общей сборкой.

## Исправленные проблемы фронтенда

### FE-001 · Нет отдельного mock.json

Приоритет P1, статус: исправлено. До продолжения задания фейковые материалы были встроены в data.ts, а требуемого отдельного файла не было.

Шаги: открыть свежий браузер, зайти в библиотеку, посмотреть Network. Ожидается загрузка mock.json. Исправление: fixture в public/mock.json, fetch-адаптер, копия рядом с сдаваемым HTML. Подтверждение: mock.spec.ts — запрос JSON зарегистрирован; submission.spec.ts — собранный HTML читает соседний файл.

### FE-002 · Повреждённая структура данных могла сломать чтение

Приоритет P2, статус: исправлено. Старый адаптер проверял только наличие массивов notes/users. Конспект с отсутствующим автором доходил до рендера Avatar и мог вызвать ошибку.

Шаги: заменить authorId первого материала в mock.json на отсутствующий ID, открыть библиотеку в свежем контексте. Ожидается понятное сообщение, а не падение страницы. Исправление: проверка структуры и ссылок до рендера, сообщение и кнопка повторной попытки. Подтверждение: mock.spec.ts, сценарий missing authors; проверен также синтаксически некорректный JSON и HTTP 404.

### FE-003 · Нерабочая первая упаковка самодостаточного HTML

Приоритет P1, статус: исправлено в процессе разработки. При встраивании minified JS через строковый аргумент String.replace последовательности `$&` в коде интерпретировались как инструкции подстановки. Первый браузерный тест сборки не получил запрос mock.json.

Шаги: собрать Vite, встроить JS в HTML строковой заменой, открыть самодостаточный HTML. Ожидается работающий модуль и JSON-загрузка. Исправление: callback в replace возвращает исходный bundle буквально; закрывающие script/style экранируются. Подтверждение: оба submission.spec.ts проходят, включая публикацию через редактор и модерацию.

## Проблема / ограничение для бэкендера

### API-001 · Нереализованные методы возвращают пустой 501

Статус: закрыто после перепроверки нового main bfcf9ae. Бэкендер реализовал методы tags, search, attachments, backlinks и graph. Замечание относилось к старому 0cb885d и больше не считается открытой ошибкой.

Где: `backend/internal/httpapi/api.gen.go`, например ListTags, SearchNotes, ListAttachments; `api` в server.go наследует Unimplemented. Заглушка выполняет только `w.WriteHeader(http.StatusNotImplemented)`. Тело JSON и Content-Type application/json не формируются.

Актуальные обработчики находятся в tags.go, search.go, attachments.go и notes.go. Сгенерированный Unimplemented по-прежнему существует как служебный каркас, но api переопределяет эти методы. Сам факт наличия каркаса не является багом. Реальные результаты сервера показаны в скриншотах бэкендера; здесь проверяется соответствующий HTTP-клиент.

### INT-001 · Path refresh-cookie не совпадал с путём фронтенд-прокси

Приоритет P1, статус: исправлено и обновлено для `/v1`. Backend выдаёт cookie с Path=/v1/auth, а браузер отправляет refresh на /backend-api/auth/refresh. Без переписывания cookie не отправлялась бы на этот путь. После переноса API запросы без `/v1` также перестали бы попадать в обработчики.

Исправление: Vite и serve.mjs направляют `/backend-api/*` на `/v1/*` и переписывают Path на /backend-api/auth. Production использует `/v1/*`. Подтверждение: 3 Node HTTP-теста прокси и браузерная проверка reload/refresh. Access-токен не хранится в localStorage/sessionStorage, httpOnly-cookie не доступна через document.cookie.

### INT-002 · Учебные данные нельзя подставить вместо моделей API

Статус: устранён архитектурный разрыв. Серверные UUID, snake_case, статусы и курсоры отличаются от учебной модели mock.json. Основной интерфейс теперь использует DTO из актуального OpenAPI напрямую, включая общую библиотеку и социальные функции. Учебная сборка остаётся отдельным режимом. Локальные демоматериалы автоматически на сервер не переносятся.

### INT-003 · Новый формат ошибок RFC 7807

Приоритет P1, статус: исправлено. Сервер перешёл на application/problem+json с полями code/detail/status. Старый клиент ожидал error.code/message, а диагностика принимала только application/json. Клиент и диагностика обновлены; проверены неверный пароль, Retry-After и квота 409 limit_reached. Несохранённый предмет остаётся в форме, сессия не теряется.

### API-002 · Строка каталога ошибок в поле версии OpenAPI

Статус: исправлено. В 06016a4 строка Markdown про method_not_allowed оказалась сразу после openapi: 3.0.3 вместо блока описания; она могла стать продолжением значения версии YAML. Строка перенесена обратно в таблицу ошибок. Типы клиента повторно сгенерированы из исправленного контракта.

### UI-001 · Стрелка у имени пользователя

Статус: реализовано. Вместо немедленного перехода к профилю кнопка раскрывает панель с профилем, материалами, избранным, темой и выходом. Проверены навигация с клавиатуры, Escape, клик снаружи и выход после reload. Дополнительные 4 браузерных сценария покрывают исходники и переносимую сборку; проверены сохранение темы и мобильная панель.

### CI-001 · Повторяющиеся падения после изменений OpenAPI

Статус: исправлено. CI останавливался до браузерных тестов на сравнении с устаревшим schema.d.ts. Типы теперь автоматически генерируются перед dev/build и не хранятся в Git; сборка проверяет актуальный контракт и API-фикстуры тестов. Проверена сборка после удаления локального файла типов. Проверки TypeScript, прокси и Playwright сохранены.

### INT-004 · Новые ограничения вложений

Статус: исправлено. В main 06016a4 разрешены только PDF/PNG/JPEG/WebP, до 3 файлов по 2 МБ на заметку. Старый клиент разрешал GIF/TXT/MD и 20 МБ. MIME, размер и количество обновлены. Браузерный сценарий проверяет отказ до регистрации/S3-загрузки, граничный размер 2 МБ, блокировку четвёртого файла и освобождение места после удаления.

### ENV-001 · API отсутствует в локальном окружении

Статус: закрыто 23 октября. Docker Engine запущен, полный стек работает локально. Новый start.ps1 поднимает также готовый фронтенд, проверяет /v1/health и выполняет seed. Сквозной сценарий прошёл через реальный Docker/Nginx-сайт; локальный Go и npm для запуска больше не нужны.
