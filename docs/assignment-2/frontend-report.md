# Вклад Frontend в следующее задание

Дата: 14 октября 2026. Проект: StudyVault — база знаний студента. Основание бэкенда перепроверено по main aa8e71d. Прокси фронтенда обновлён для API `/v1` и нового пути refresh-cookie `/v1/auth`.

Работа выполнена со стороны фронтендера с небольшим вкладом в тестирование. Бэкенд, документ аналитика и презентация о деплое не входят в этот вклад. Публикация изменений в Git не означает размещение сайта на хостинге.

## Результат для тимлида

Сдаваемые файлы:

- `deliverables/frontend/index.html` — рабочий интерфейс с включёнными CSS/JavaScript.
- `deliverables/frontend/mock.json` — отдельные фейковые данные (5 студентов, 8 опубликованных материалов, 2 на проверке).
- `deliverables/frontend/README.md` — порядок просмотра и пересборки.
- `docs/assignment-2/screenshots/` — скриншоты работающей сдаваемой сборки.
- `docs/assignment-2/bug-reports.md` — баг-репорты и границы проверки.
- `docs/assignment-2/api-check.json` — фактический результат проверки доступности API из браузера.

Исходники React/TypeScript и Playwright-проверки находятся в `frontend/`. Начальные данные читаются fetch-запросом из mock.json, затем локальные действия сохраняются в браузере. Фронтенд не ожидает завершения API.

После обновления бэкенда добавлен отдельный «Кабинет API»: реальные HTTP-запросы входа/регистрации, предметов, заметок, поиска, тегов, графа и вложений. Типы генерируются из его OpenAPI. Учебный режим сохраняется для требования index.html + mock.json. Кабинет не приписывает серверу комментарии, рейтинг и модерацию, которых пока нет в контракте.

## Что можно показать

Найти конспект через поиск и фильтры → открыть → оценить → сохранить в избранное → написать комментарий. Создать материал в редакторе → сохранить черновик или отправить на проверку → одобрить демомодератором → увидеть в библиотеке. Дополнительно: выгрузка Markdown, удаление своего материала, профиль, рейтинг, мобильная версия.

Ошибка загрузки mock.json имеет понятное описание и кнопку повторной попытки. Пустая библиотека, повреждённый JSON и ссылки на отсутствующего автора проверяются отдельно.

## Проверки

`npm run package:submission`: TypeScript и production-сборка, затем подготовка двух файлов. `npm test`: 24 браузерных сценария — учебная библиотека и её ошибки, переносимый HTML, адаптивность и настоящий HTTP-клиент на подставленных ответах контракта. `npm run test:proxy`: 2 проверки передачи JSON, Bearer/cookie, курсора, Path refresh-cookie и ограничений маршрутов. Добавлен frontend CI, включая проверку актуальности сгенерированных типов. Подробности — в [баг-репортах](bug-reports.md).

На этой машине API на localhost:8080 не был доступен. Go не установлен, Docker daemon не запущен. Поэтому запуск реального API, положительная проверка регистрации и CRUD требуют проверки бэкендером/тестировщиком в их окружении. Фронтенд при этом полностью демонстрируется на mock.json.
